A garden in a box for AI agents.

From hakoniwa (箱庭), the Japanese miniature garden in a box.

Hakoni explores a simple idea: hand someone one link, let their general-purpose coding agent (Claude Code, Codex…) read it, and end up with a small, sandboxed work environment that already knows its job: its tools, its rules, its knowledge and its place in a shared project.

Early exploration. Nothing is built yet: this page describes hypotheses being tested, not a product.

Why

Agents are becoming useful to people who are not developers, but handing one over is still hard. Today you share a prompt, a few instructions and a lot of manual setup. Hakoni asks what it would take to hand over a whole small work environment as easily as you send a file.

Two experiments started the idea. In the first, an onboarding Markdown file behind a Git link was enough for someone's coding agent to join a project: clone it, take its own branch and folder, prepare its environment, find the plan and the conventions. In the second, a sandbox container held everything a specialised task needed (tools, skills, rules, configuration), so that any agent connected to it over SSH could do the job from a plain-language request, with nothing installed on the agent's side.

Hakoni brings the two together.

The idea in four parts

The seed

An onboarding document behind a Git link: the mission, the prerequisites, how to join.

The box

A sandboxed container: the delivery unit, with its tools, skills, conventions and access policies.

Git

Carries the recipe, the shared knowledge, the contributions, the work log and the continuity between sessions.

The agent

Interchangeable. It installs the environment with the user's permission, then works inside it.

From one link to a working garden

The path being prototyped, not yet validated end to end:

  1. The recipient gives the seed link to their coding agent.
  2. The agent reads it, detects missing prerequisites, explains them and asks before installing anything.
  3. It fetches the reviewed container recipe, builds and starts the box.
  4. It connects to the box and continues the bootstrap inside the sandbox.
  5. It sets up Git with the recipient's own identity, clones the project and joins its branch.
  6. It works, logs what it did, and at each new session catches up on what changed.

The host bootstrap is a trust boundary: the seed is untrusted input until its provenance is checked, and an instruction in a repository never authorises leaving the sandbox on its own.

A box with clear edges

The container is the perimeter of the mission, not a security guarantee on its own. Hakoni aims for least privilege: explicit file access, allowed network destinations only, the user's own identity and secrets provided at run time, never baked into the image, and no Docker socket or privileged host access by default.

After the spreadsheet?

A lot of everyday business computing runs on spreadsheets and hand-made tools built outside any IT project. A spreadsheet bundles data, logic and practice in one transmissible file. A Hakoni could bundle instructions, skills, tools, conventions, access policies and a workspace in one transmissible link, driven in natural language, without a new central platform for each small use.

Can we finally kill Excel?

The question is provocative on purpose, and still open.

Hakoni builds Hakoni

The first Hakoni project is Hakoni itself. The same seed link is given to Claude Code and to Codex, on two separate installs; each should reach an equivalent environment, make a contribution and resume a session. Every difficulty met along the way is a real product friction to fix.

Hakoni is an open exploration. Source, vision and plan: github.com/mdussere/hakoni. Apache 2.0.
